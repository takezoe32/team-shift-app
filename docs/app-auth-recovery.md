# Firestoreアクセス期限切れからの復旧

## 修正内容
- GoogleのIDトークンをサーバーで検証し、既存 `app_data/shared_state.users` の登録メールと照合する。
- 登録済みのIDを使うFirebaseカスタム認証へ変更。初回管理者の自動作成は廃止する。
- Firebaseが保持するセッションを復元してから共有データを読み込む。localStorageのプロフィールだけでは読み書きできない。
- 読込拒否・原本不在は専用エラー画面にし、空のデータで画面を開かない。
- ルールは期限なしの登録メンバー認証へ変更。閲覧専用は読取だけ。専用連携領域はクライアントから拒否する。
- 退会や閲覧専用への変更は、古いトークンが残っていても最新の登録情報で判定する。
- 管理者以外の権限・メンバー一覧変更を禁止。本人の表示名・プロフィール画像の変更は許可。

## 本番への適用順
1. Firebaseコンソールの対象プロジェクトが `team-shift-app` であることを確認する。
2. `Authentication` が未初期化なら「始める」を押す。今回のカスタム認証にGoogleプロバイダの有効化は不要。既存Google OAuthを引き続き使う。
3. アプリの認証修正をProductionへ反映する。既存の期限切れルールのままでは、この段階ではデータは表示されない。
4. Firestore「ルール」の現在の内容を控え、リポジトリの `firestore.rules` 全文に置き換えて「公開」する。原本ドキュメント自体は編集しない。
5. アプリを再読み込みし、一度Googleログインする。過去の端末内プロフィールだけでは認証されないため、移行時の初回ログインは必要。
6. 既存のメンバー・シフト・タスク・在庫の表示を確認する。再読み込み後に再ログイン不要なことを確認する。
7. 登録外アカウントの拒否、閲覧専用アカウントの書込み拒否、通常メンバーのプロフィール更新、管理者のメンバー変更を確認する。

## 注意
- 本修正のサーバー設定は既存の `FIREBASE_SERVICE_ACCOUNT_JSON` / `REPORT_AUTH_SECRET` / `GOOGLE_CLIENT_SECRET` を使う。秘密値の再発行やチャットへの貼り付けは不要。
- カスタムトークンの署名はサーバー内の既存サービスアカウント鍵で行う。秘密鍵をブラウザへ返さない。
- データ削除・初期化・期限延長による未認証アクセスの再開は行わない。
- Firestoreルールの変更だけ、またはアプリの変更だけでは復旧しない。両方の適用が必要。
- 原本の全レコードの完全性と実アカウントでのログイン・書込みは本番確認が必要。ローカルのテストは模擬データを使う。
