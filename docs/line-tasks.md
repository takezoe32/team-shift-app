# LINEからのタスク登録・申し送り

## 個別トーク（推奨）
公式アカウントを友だち追加し、個別トークに「タスク」または「追記」を送る。メンションは不要。グループへの参加を全員に求めない。

初回のみ、アプリの「使い方」→「LINEから登録」→「LINEと連携する」を押す。LINEログインで本人確認し、公式アカウントの友だち追加を許可する。コードの発行・コピー・メール送信は不要。アプリのGoogleログイン時に登録済みメンバーの本人確認用HttpOnly Cookieを発行する。以前からログイン中などでCookieがなければ、同じGoogleアカウントで一度本人確認して続行する。LINE側のメール取得権限は使わず、アプリ側で確認した登録メールとLINE IDを結び付ける。

サーバーはGoogle IDトークンの署名・audience・有効期限・email_verifiedを確認し、登録メールが一意のメンバーだけに本人確認Cookieを発行する。LINEログインには10分有効・一回限り・ブラウザーCookieで拘束したstate、nonce、PKCE S256を使う。トークンはLINEの検証APIで確認し、実際のMessaging APIのプロフィール取得でも同じLINE IDが利用できることを確認する。トークンは保存せずブラウザーに返さない。完了直前にも登録メール・役職・連携解除の世代を再確認する。1メンバーに1LINEを対応させ、別のLINEへ再連携すると旧LINEの操作は拒否する。毎回の操作でもメンバーの存在・メール・閲覧専用・対応の失効を確認する。従来のコード連携APIは互換用に残す。

## LINEログインの初回設定（管理者のみ）
1. LINE Developersの既存プロバイダー「The LUIGANS 管理課」内に「LINEログイン」チャネルを追加する。Messaging APIとは必ず同じプロバイダーを使う。
2. アプリタイプをWebアプリにし、プライバシーポリシーに https://team-shift-app.vercel.app/privacy.html を設定する。
3. LINEログイン設定のコールバックURLを https://team-shift-app.vercel.app/api/line-login に設定する。
4. 「リンクされたLINE公式アカウント」に「管理課 タスク受付」を指定する。
5. チャネルを公開状態にする。開発中のままでは一般メンバーがログインできない。
6. Vercel Productionに LINE_LOGIN_CHANNEL_ID と LINE_LOGIN_CHANNEL_SECRET を追加して最新mainを再デプロイする。Messaging API用のID・Secretとは別の値。Secretはチャットやソースに貼らない。
7. アプリから本人確認→LINEログイン→許可・友だち追加→連携完了を確認し、個別トークで「タスク」を試す。準備前はボタンを無効にし、初回設定待ちと表示する。

メンバー一覧は名前の横に小さく「LINE」を表示する。共有データには登録済みメールとの一致用の連携印だけを記録し、LINE ID・表示名・トークンは公開しない。従来の連携済みメンバーは次の個別トーク操作時に印を補完する。全体の連携解除で全員の印も消す。メール変更・閲覧専用への変更では印を表示しない。

「タスク」→種類選択→記入フォーマット→確認→登録。「件名」「日付」「内容」（任意）、パートナーは「時間」「パートナー」も記入する。日付は「明日」も可。未入力・無効な日付や時刻があればフォーマットを返してまとめて修正できる。個別トークでは本人名の選択はなく、メールアドレスで確認した本人を担当者にする。パートナー名候補確認は必要時のみ。全項目が有効でも「登録」を押すまで共有データへ書き込まない。「修正」は内容を保持したフォーマットへ戻る。

「追記」→種類・番号で対象選択→文章・画像・動画を送信→最新の確認ボタンで追加。個別トークでは文章をそのまま送れる。「内容：」「追記 内容」も使える。画像だけ・動画だけの申し送りも保存できる。文章を送り直すと本文を置き換え、添付は保持する。個別トーク内の返信にはreplyTokenだけを使用し、グループ送信やpush APIは呼ばない。入力中のメッセージは本人だけ、保存後のタスクはアプリの共有対象者に見える。

添付は画像5枚（各10MB以下）、動画1本（30秒・25MB以内）。署名検証・本人確認後、選択中タスクと本人の入力セッションがあるときだけ受け付ける。グループや未連携ユーザーの画像、外部URLのメディアはダウンロードしない。LINE専用ホストからサイズ制限付きストリームで取得し、既存のCloudinary unsigned preset `teamshift_tasks`へ保存する。LINEアクセストークンはLINE以外へ送らない。動画再生URLはアプリ既存の互換変換を使う。受信状態・処理リース・保存済みメディアのキャッシュはサーバー用領域に保管し、複数画像の受信途中やエラー中の確定を拒否する。LINEのimageSetでは全枚数を受信するまで待つ。準備中（202）やエラーでは再試行・添付除外・キャンセルのボタンを返す。

ファイルは受信時にCloudinaryへ転送するが、確認前は共有タスクへ追加しない。受信中に入力のキャンセル・別タスクへの変更・認可失効が起きたらタスクには反映しない。キャンセル・失敗によって未参照となったCloudinaryファイルの自動削除は行わない。利用中のunsigned presetはpublic_idを自動生成するため、冪等性はサーバーの処理リース・キャッシュとタスク書き込みのIDで保証する。クラッシュ直後の再試行では未参照ファイルが残る可能性がある。

個別利用の許可と、メンバー対応・登録入力・申し送りセッションはユーザーごとに分離し、グループ操作とも分離する。連携解除は認可世代を変更し、個別トークも停止する。再開後も以前の認可は自動復活せず、もう一度LINE連携が必要。連携しただけではタスクは作成しない。

## APIの初回設定・従来のグループ操作
1. LINE公式アカウントを作り、Messaging APIを有効にする。
2. グループトークへの参加を許可し、あいさつ・自動応答メッセージをオフにする。
3. Vercel Productionに Secret として LINE_CHANNEL_SECRET と LINE_CHANNEL_ACCESS_TOKEN（長期）を設定する。値をソースやチャットに貼らない。
4. 最新 main を本番デプロイする。過去のデプロイを再デプロイしない。
5. LINE Developers の Webhook URL を https://team-shift-app.vercel.app/api/line-webhook に設定し、検証成功後 Webhook と再送を有効にする。
6. 公式アカウントを自分のLINEに友だち追加し、業務グループへ招待する。
7. 管理者のアプリ「設定」→「LINEタスク連携」を開く。必要なら日報と共通のGoogleログインを確認する。
8. 「グループ連携コードを作る」で表示された LINE連携 + コード の一行を10分以内に、LINEの候補から公式アカウントをメンションした後に貼り付けて投稿する。選んだ1グループのみ受け付ける。別グループで新コードを使用すると切替となる。

## 利用
LINEの「@」候補から「管理課 タスク受付」を選んでメンションし、続けて「タスク」と書き、空白・コロン・改行のあとに内容を書く。
例：
タスク
日付：明日
件名：217号室の防水調査
時間：10:00
パートナー：山下健装

投稿本人がメッセージ内のメンバー／パートナー／キャンセルのいずれかを選ぶ。選択期限24時間。
選択した種類の必要項目が揃えば共有タスクへ登録。不足項目は投稿者本人へLINEで質問し、回答後に登録する。
「日付」「対象日」「担当」「担当者」「時間」「開始」「件名」「内容」「会社」「パートナー」のラベルを使用できる。
年なしの過去日、複数の日付、午前午後指定、曖昧な時刻は推測せずLINEで正しい値を聞き返す。担当者は投稿者を使用する。
15分刻み以外のパートナー開始時刻はLINEで再入力を求める。メンバータスクは開始時刻を必要としない。
画像・動画・過去のトーク一括取得・既存の本文や申し送りのLINEからの編集は対象外。外部AI APIを呼ばない。

## 保存と安全性
署名は未加工の本文で検証。連携設定・一時受付は _server_integrations 以下のみで保存し、匿名読み取りが許可されている場合は拒否。
管理者セッションとCSRFが連携・要確認登録に必要。LINE投稿のタスクは投稿者のアプリ上のメンバーを登録者・担当者とする。グループ参加者による「タスク」投稿を受付対象とする。
グループ・投稿者の一致、期限、受付状態をサーバーで検証。Firestore commit の更新時刻条件で受付状態と共有タスクを同時保存し、競合を再試行する。
投稿内容や秘密値はログに出さない。アプリの連携解除は今後の受信を止め、保存済みタスク・受付記録は削除しない。
確認待ち一覧は最大100件。保存領域やサーバーの既存プランの利用量は別途監視する。

## 申し送り
登録済み返信の「申し送りを追加」ボタン、または「@管理課 タスク受付 申し送り 件名」の検索から対象を選ぶ。
「@管理課 タスク受付 追記」で未終了の公開メンバータスクとパートナータスクの一覧を表示する。種類を選ぶと縦一覧で10件ずつ表示し「次の10件」で切り替え、最後からは最初に戻れる。対象は「@管理課 タスク受付 3」のようにメンションと番号を送って選択し、種類選択にも戻れる。今日、期限を過ぎた未終了（新しい日付順）、今後（日付順）の順に並べる。個人メモは除外する。「@管理課 タスク受付 申し送り 件名」では終了済みも含めて検索でき、検索結果も同じ方法でページを切り替えられる。
本文は「@管理課 タスク受付 追記 内容」と投稿し、確認カードの「このタスクに追加」を入力本人が押す。
グループ・入力者別の専用サーバー領域で入力を保持し、30分で失効。通常の会話を本文にしない。
本文の送り直しは旧確認ボタンを無効化。イベントの受付記録を同時commitし、再送された検索や選択で新しい入力を巻き戻さない。
タスクが移動していてもIDと登録者から検索し直し、削除・非公開になっていれば保存を拒否する。
元の文章・画像は変更せず、kind=handoffで追加。作成日時とLINEから得られた表示名（取得できない場合はLINE投稿者）を記録する。
このグループの参加者はLINE経由で公開タスクへ申し送りを追加できる。アプリ利用者と個別のLINEアカウント紐付けは行わない。
LINEユーザーの表示名確認には公式グループメンバープロフィールAPIを使用する。


## メンション必須
メンションだけ（後ろが空白・改行だけの場合も含む）を送ると、追記・タスク登録・件名検索・番号選択・本文追記の案内を返す。案内表示で入力中の申し送りやタスクは変更しない。
全テキスト投稿（新規登録、追記の開始・本文・番号、グループ連携コード）は受信した公式アカウントへの正式なメンションを必要とする。名前の手入力、他人へのメンション、@Allでは反応しない。署名検証後にLINEのmention.mentionees.isSelfを確認し、未提供時のみdestinationとuserIdを照合する。公式アカウントのメンション部分だけを除いてコマンドを解釈する。表示済みのpostbackボタンはメンション不要で、従来の本人確認・期限確認を維持する。「追記」単独は開始コマンドの別名で、対象を選んだ後の「追記 内容」は本文として扱う。「申し送り」もメンション付きで引き続き使える。


## 管理者不要の入力補完
担当者は投稿した本人の1名に固定し、本文の担当ラベルによる他人への割り当ては行わない。連携済みの対応を優先し、未設定ならLINE表示名とアプリのメンバー名が一意に一致する場合に照合する。一致しない場合・プロフィール取得不可の場合は初回に自分の名前を選択し「本人です」で確認する。選択した対応はグループ・LINEユーザーごとにサーバーへ保存する。閲覧専用メンバーは対象外。これは連携グループ内での自己申告による対応であり、アプリへのログイン認証の代替ではない。
種類選択後、日付・件名・パートナー名・開始時刻の不足を順にLINEで質問する。質問への回答も正式なメンション必須。名前が一覧に完全一致しないパートナーは文字の類似度で候補を最大2件表示し、本人の確認後に正式名で登録する。新規名の場合も明示的な登録ボタンが必要。日付・15分刻み時刻は再検証する。登録完了まで管理者の確認待ちにはせず、期限24時間・本人制限・古いボタンの拒否・重複登録防止を維持する。アプリに担当者として選べるメンバーが存在する必要がある。以前の要確認一覧は既存候補の救済用に残す。
