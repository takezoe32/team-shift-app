# 検針の共通マップ

毎朝検針のマップは `_server_integrations/meter_map` に保存します。Firestoreの既存ルールでクライアントからの直接読み書きは拒否し、認証済みの検針APIを通します。

- 検針を利用できるメンバーは共通の番号・配置・検針項目を読み込みます。
- 登録・番号変更・移動・削除は管理者のみ。保存直前に共有原本の最新権限を確認します。
- 保存は配置のバージョンを照合するトランザクションです。他の管理者の更新を上書きせずエラーにします。
- 配置変更は自動でサーバーへ保存し、成功を画面に表示します。失敗時は保存済みの配置に戻し、エラーを表示します。
- 旧版で端末に登録した配置は、共有マップがまだない場合に限り、管理者の確認を経て初回移行できます。共有マップが登録済みの場合は端末の配置で上書きしません。
- 配置ファイルの保存・読込ボタンはありません。一般ユーザーには配置編集ボタンも表示しません。

共通マップは日次バックアップに含まれ、データ保護画面からの復元で共有原本と一緒に戻せます（docs/daily-backup.md）。

配置は原本の検針値と別の保存先です。検針値の保存は従来どおり確認画面と原本APIを使います。共有マップの更新は、ほかのユーザーが検針画面を開き直すと反映されます。

検証: `node --test tests/meter-map.test.mjs tests/meter-readings.test.mjs`。ブラウザー検証では、別々のユーザー環境で旧配置の移行、共有配置の表示、管理者の番号変更、一般ユーザーの検針入力と編集ボタン非表示を確認します。

## 固定マップからの入力

一覧／マップの切り替えと原本リンク・通常の再読込ボタンは表示しません。毎朝検針を開くとマップが表示されます。スマホ縦画面は上にマップ、下に選択位置の入力欄、横画面やPCは左右に分けます。マップと入力欄は画面内に固定し、項目数が多い場合は入力欄だけがスクロールします。拡大縮小はピンチ・ボタン、移動はドラッグ／1本指で行えます。

番号ごとの保存はありません。回る順番は人によって違うため、次の番号は毎回マップ上で押して選びます（「次へ」ボタンはありません）。入力欄でEnterを押すと同じ番号の次の項目へ移り、最後の項目ではキーボードが閉じます。マップ上のすべての番号の項目が入力されると「保存内容を確認」が押せるようになり（それまでは押せない状態で表示）、全項目をまとめて原本へ保存します（数式セルは入力済み扱い）。未入力がある間は、残りの番号を入力欄の下に表示します。丸い番号の色は、青＝未入力、薄い緑＝一部入力、緑＝入力済み、オレンジ＝選択中です。

キーボードの表示・非表示で画面の高さが変わっても、拡大率とマップの表示位置は変えません。スマホの左右分割は端末の向きで決め、キーボードで枠が横長になっても切り替えません。端末を回転したときだけ表示中の中心を保ったまま再配置します。

画面の利用可能範囲はアプリのヘッダー・下部メニュー・Visual Viewportに追従します。ただしキーボード表示時（幅が同じまま高さが120px以上減ったとき）は、マップと入力欄の大きさをキーボードが出る前のまま固定し、狭くしません。アプリ側の枠はキーボードより上の範囲に収め、マップのページ（public/meter-map.html）にキーボード前の高さ（meter-map-keyboard）を伝えます。マップのページはその高さを保ったまま自分自身を上下にスクロールするので、入力欄・余白のどこを触ってもスクロールでき、マップ上の1本指の上下操作も、マップがそれ以上動かない分はページのスクロールになります。入力中の欄（Enterで移った欄を含む）は自動でその範囲に表示します（src/meterFrame.mjs）。横持ち用の小さい表示（html.short）は入力中には切り替えません。検針画面ではアプリ上部のアプリ名・使い方・ログイン表示を隠します（下のメニューは残ります）。キーボードを閉じる・回転する・アドレスバーの伸縮では従来どおり追従します。キーボード表示時もマップを残し、入力中の値とフォーカスを維持します。入力途中の値は同日のメモリに保持し、別番号を選んでも保持します。日付変更や画面移動時の未保存確認にも反映します。原本保存は従来の確認画面から行います。

ブラウザー検証: 390×844、375×667、320×568、1440×900、844×390で画面全体の縦スクロールがないこと、入力確認ボタンの表示を確認。キーボードを想定した高さ変更で入力値・フォーカス保持と保存確認を確認。20項目を設定して入力欄だけのスクロール、ピンチ・移動と管理者限定の共有配置操作も確認しています。

入力中は、まだ保存していない入力値の一覧（新しい順、入力した時刻・番号・場所・項目・値）をマップと入力欄の下に表示します（毎朝検針・毎月検針とも）。画面を下へスクロールして見るので、マップと入力欄の大きさは変わりません。一覧の行を押すとその番号を開きます。原本に保存すると一覧は消えます。

## 毎月検針

メニューの「毎月検針」は、毎朝検針と同じ画面構成（ホテル1階の図面＋入力欄）で、部門メーター 2026年（毎月検針）の原本（`src/meterMonthly.mjs` の `MONTHLY_FILE_ID`）の「2026年度（令和8年）」シートへ保存します。検針月を選び（初期値は今月）、その月の「○月度」行に書き込みます（電気は5＋2×月、ガスは40＋2×月、水道は74＋2×月の行）。

- 原本の21項目のうち、アプリで入力するのは毎朝検針の原本にない11項目（②研修棟、③ガーデン受電盤、④テニスコート、⑤マリン主メーター、⑧バンケット主厨房、⑨プール×3、⑩従食、⑪8F厨房、⑫大浴場給湯器、⑰プール、⑱RF中水）だけです。マップにはこの11項目だけを登録できます。
- 残りの10項目は保存時に毎朝検針の原本から自動で転記します。①全日電力・⑥本館系統・⑦バンケット系統・⑬ボイラー・⑭新厨房・⑮ホテル系統・⑯バンケット系統・⑳給湯は、シート「月」の1日の値です。⑲日比谷花壇は、シート「H-月」の水道の1日の値です。デマンドは前月シートの最大値です。全日電力のメーターは2026年10月に一周したため、11月度以降は毎朝検針の値に100,000を足して転記します（例：11/1の575.5 → 100,575.5。`MONTHLY_ROLLOVERS`）。転記する値が前月より小さい場合は、確認画面に注意を表示します。
- 保存確認画面に、入力した値と転記する値（原本の現在値→転記値）を表示します。毎朝検針の1日がまだ空欄の項目は転記せず、その旨を表示します。毎朝検針に値が入ったあとで、もう一度保存すると転記されます。原本と同じ値・数式セルには書き込みません。
- 毎月検針のマップは毎朝検針とは別の共通マップ（`_server_integrations/meter_map_monthly`）です。登録・変更は管理者のみです。日次バックアップにはまだ含まれていません。
- 原本の月の行（「○月度」）や項目名の並びが想定と違う場合は、読み込みを止めて保存しません。

検証: `node --test tests/meter-monthly.test.mjs`。実原本のコピーで確かめる場合は `METER_TEST_XLSX`（毎朝検針）と `METER_MONTHLY_TEST_XLSX`（毎月検針）を指定します。
