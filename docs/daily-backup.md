# 自動バックアップ・不具合通知

## 毎日の保存
- 既存のVercel Cron `/api/daily-report-cron` を使用。日本時間の午前0時台に1回、アプリを開いていなくても共有原本 `app_data/shared_state` の全フィールドを保存します。
- 日報のDrive保存とは独立して実行し、一方が失敗してももう一方を実行します。Cronの認証 `CRON_SECRET` とProduction制限は維持します。
- `_server_backups/YYYY-MM-DD` とその `parts` サブコレクションへ、Firestoreの型を保持した原文をgzip圧縮・分割保存します。日時、64bit整数、バイト列等を復元時に変換しません。
- SHA-256と復号後の長さを検証します。同日分は作成済みなら上書きしません。保存と再読取検証が成功した後だけ、30日より古い日次バックアップを削除します。原本が不在・メンバーが空のときは作成せず、既存の履歴を保持します。
- 毎朝検針の共通マップ `_server_integrations/meter_map` も同じバックアップに含めます。マップはJSON文字列としてSHA-256付きで保存し、読み取り時に検証します。マップが未登録の日は「含まれていない」と記録します。
- 復元前の退避コピーは `before-restore-*` として別途保持します。日次の30日整理では削除しません。
- 現在のFirestoreルールはバックアップ・通知領域をブラウザから拒否するため、ルールの追加変更は不要です。

## 管理画面
- 設定 →「データ保護・バックアップ・不具合通知」。原本を開けない場合も https://team-shift-app.vercel.app/#data-safety へ直接アクセスできます。
- 管理者Googleアカウントで再確認します。権限はlocalStorageではなく、署名・audience・期限を検証したGoogle IDトークンと既存REPORT_ADMIN_EMAILS（既定：mitsutake.takezoe@plandosee.co.jp）で判定します。
- 「本日分を保存」で初回バックアップを作成し、一覧に表示されることを確認します。翌日以降は自動です。
- 復元は対象の「復元内容を確認」→件数確認→「この時点へ復元する」→確認ダイアログ。共有原本が削除された場合も、管理者はこの画面から復元できます。
- 復元直前の状態（共通マップを含む）を退避し、確認画面を開いてから原本に変更があれば中止します。復元後はメンバー・権限も過去の状態に戻ります。
- 共通マップを含むバックアップでは、共有原本とマップを1回の書き込みで同時に戻します。どちらかが復元の直前に変更されていれば両方とも中止します。戻したマップには現在より新しいversionを付け、復元前に開いていた管理者画面からの上書きを防ぎます。マップを含まない以前のバックアップを復元しても、現在のマップは変更しません。確認画面に検針マップの箇所数を表示します。実データの復元はテストのためには実行しません。

## 通知メールの初期設定
- 送信元：mitsutake.takezoe@plandosee.co.jp（通知先と同一）
- 宛先：mitsutake.takezoe@plandosee.co.jp（ユーザー確認済み）
- 送信元Gmailで2段階認証を設定し、Googleアカウントの「アプリ パスワード」で送信用のパスワードを発行します：https://myaccount.google.com/apppasswords
- Vercel → team-shift-app → Settings → Environment Variables に `ALERT_SMTP_PASSWORD` をSecret、Production用として追加します。値はGmailのアプリパスワードです。通常のGoogleログインパスワードを使わず、チャットやGitHubへ貼り付けません。
- 保存後にProductionをRedeployし、データ保護画面の「テストメールを送信」から受信を確認します。未設定時は画面に「未設定」と表示し、メール送信が有効と誤表示しません。
- バックアップ失敗、日報の自動保存失敗、ログイン中のFirestore読取失敗、アプリのwindow.error/unhandledrejection、一部の共有保存処理失敗を通知対象にしています。ユーザーの入力内容・画像・スタック・秘密値はメールへ含めません。
- 同じ種類の障害メールは原則日本時間で1日1回。通常時はFirestoreの予約・完了記録で重複を抑止します。送信失敗時は10分後から再試行可能です。メール送信成功後の記録失敗などでは重複する可能性があり、SMTPで厳密な一度限りの配信は保証しません。
- 保存先への接続自体が失敗している場合、認証済みの定期処理だけはプロセス内の抑止を使って通知を試みます。ブラウザからの通知要求は予約領域に接続できなければメールを送信しません。

## 保護範囲と運用上の制約
- 日次バックアップのため、最後の保存後に入力した分は復元対象に含まれません。
- 添付画像・動画・ファイルのリンクと登録情報は含みますが、Cloudinary/Google Driveにあるファイル本体の複製ではありません。
- 保存先は同じFirebaseプロジェクト内の別コレクションです。誤操作・原本削除からの復旧用であり、Firebaseプロジェクト全体の削除やクラウド全体の障害に備える別媒体のバックアップではありません。
- Google OAuth/LINE等のサーバー専用連携情報は複製対象にしていません。原本の業務データ全体と共通検針マップが対象です。
- Vercel HobbyのCronは0時台の実行で、分単位の定時保証・失敗時の自動再試行保証はありません。Cron登録・初回保存・翌日分の自動保存を管理画面で確認してください。
- 通知設定が壊れた場合や、Vercel全体・ネットワーク・Gmailが停止した場合は送信できません。アプリを開いていない間のサイト全停止を即時検知する外部監視は含まれません。
