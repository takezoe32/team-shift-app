# 毎朝検針

「その他 → 毎朝検針」で2026年の積算メーター原本を読み書きする。

- 原本IDは src/meterReadings.mjs の固定値。毎月検針は従来の原本リンクのまま。
- 日報で設定済みのGoogle Drive連携アカウントをサーバー上で使用する。原本に編集権限が必要。追加のOAuthスコープ・公開共有は不要。
- Googleスプレッドシート形式が必要。Excel互換編集のままのファイルはSheets APIで読み書きできない。変換後にIDが変わる場合は固定IDの変更が必要。
- 利用者は既存のGoogle本人確認セッションを使用。登録メンバー・メール・閲覧権限をサーバーで再検証する。セッションがなければGoogle本人確認を案内する。
- 月タブの全半角Hと先頭ゼロを吸収。原本の年度・日付行・各列の項目見出しが一致しない場合は更新を止める。
- 前日は実際の暦日の値を取得する。月初は前月タブの末日。1月1日は前年原本が未設定のため前日未記録。
- 前日の値は表示専用。前日比は検針値の単純差で、原本の使用量換算係数は掛けない。
- 確認済みの当日入力セルだけをRAW数値で更新。空欄による既存値の削除、数式セルや文字セルの上書き、任意列指定は禁止。
- 読込内容を署名・暗号化した確認トークンを発行し、保存前に再読込して差異を検出する。アプリ同士の同日保存はFirestoreの短時間ロックで直列化する。Google Sheets画面での直接編集を完全にロックする機能ではないため、保存の瞬間の直接編集との競合は完全には排除できない。
- 保存後も原本を再読込して値を照合し、照合成功時のみ保存完了を表示する。通信失敗・競合時は入力を残す。再読込と日付変更は未保存の破棄確認を行う。
- サンプルの仮の前日値は本番に含めない。サンプルの備考欄には原本の対応列が未確定のため、本番の初回リリースは指定された20個の数値項目のみを対象とする。

検証: `node --test tests/meter-readings.test.mjs`。実際の原本にテスト値を保存しない。

- plandosee.co.jpの登録メールのみ利用可能。その他のドメインには毎朝・毎月検針ボタンを表示しない。毎朝検針の画面とAPIでも同じ制限を行い、本人確認済みメールとサーバー上の登録メールを両方検証する。
