# 来年の検針・勤務表ファイルの自動作成

毎年12月1日の夜間処理（`/api/daily-report-cron`、日本時間0時）で、翌年の次のファイルを今年のファイルから作ります。いずれも共有ドライブ「TLF」の中です。

| 作るもの | 場所 | 名前（2027年の例） |
|---|---|---|
| フォルダ | 002 積算メーター | `2027年度（令和9年）` |
| 毎朝検針 | 上のフォルダ | `積算メーター2027年（毎朝検針）.xlsx` |
| 毎月検針 | 上のフォルダ | `部門メーター 2027年（毎月検針）.xlsx` |
| 勤務表 | 001 シフト表 | `勤務表-2027年（令和9年）.xlsm`（元がxlsxならxlsx） |

- 作るのは足りないものだけです。登録済み、または同じ名前で既にあるものは作り直さず、そのまま使います。今年のファイルはダウンロードして読むだけで、変更しません。
- 12月中は毎晩確認し、1月にもまだ足りなければ作ります。失敗した日は管理者にメール（`year_files_failed`）が届き、翌晩もう一度試します。作成したときと、手で直す箇所があるときは `year_files_created` のメールで、作ったファイル名と確認事項を知らせます。
- 各年のフォルダ・ファイルのIDは Firestore の `_server_integrations/year_files` に記録します（2026年分は `api/_lib/year-files.js` の `BASE_YEAR_FILES` に固定）。検針画面はここから、その年の原本を開きます。
- 作成には、日報で使っているGoogle Drive連携アカウントが、共有ドライブ「TLF」にファイルを追加できる権限（コンテンツ管理者以上）を持っている必要があります。共有ドライブのアイテム数が上限に近いため、上限に達すると作成できません。

## ファイルの中身（`src/yearRollover.mjs`）

数式・書式・シート構成・マクロはそのまま残し、数式の前年の計算結果は消して開いたときに再計算させます（`api/_lib/xlsx-rewrite.js`）。

- **毎朝検針**：全シートの年の表示（令和・西暦）を+1。01〜12・H-01〜H-12の日付と曜日を新しい年に合わせ（2月の29日もこれで増減）、日の行と「翌月1日」の行のD列以降の入力値（検針値・稼働率・婚礼・宴会など）を空にします。下の「電気・水道使用料計算書」は残します。
- **毎月検針**：シート名と年の表示を+1（例：`2026年度　（令和8年）` → `2027年度　（令和9年）`）。各月度の行と使用量の行のうち、検針項目の列だけを空にします。
- **勤務表**：1〜12と000シートの年（3行目）を+1、曜日を新しい年に合わせます。メンバー名は今年の12月シートの並びを全シートに入れ、シフト欄（D〜AH列）と特記事項を空にします。休暇消化集計の数値と、休館日シートの日付も空にします（休館日は毎年変わるため）。その月の日数が今年と違う場合（うるう年の2月など）は、日付と曜日を変えずに、手で直すよう知らせます。12月のメンバーが行数より多い場合も知らせます。

## 年をまたぐ検針

- 1月1日の前日比、1月初めの「3日連続」の判定は、前年のファイルの12月から読みます。
- 毎月検針の1月度は、前月を前年の12月度、デマンドを前年12月の最大値から転記します。
- 翌年の原本ができるまで、その年の日付・月は開けません（「前年の12月1日に自動で作成されます」と表示）。

検証: `node --test tests/year-files.test.mjs`。実ファイルでの確認は `METER_TEST_XLSX`（毎朝検針）、`METER_MONTHLY_TEST_XLSX`（毎月検針）、`SHIFT_TEST_XLSM`（勤務表）を指定して実行します（手元のコピーで作るだけで、ドライブには書き込みません）。
